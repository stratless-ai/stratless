# Commands

```
stratless init       keep your history safe (add --auto for background refresh)
stratless profile    see the model of you — free, instant (--read: your copy)
stratless update     judge what's new; rebuild + load the profile when due (--now: always)
stratless patterns   the evidence behind your profile: every claim, numbered, with receipts
stratless receipt    prove a claim: the raw exchanges behind it (receipt 3, or a hash prefix)
stratless stop       turn it off, and unload the profile
stratless status     stratless's own state and what it has cost (--check: newer version?)
stratless stats      raw counts, instant, free, no tokens
```

## `init`

```
npx stratless init
```

Turns stratless on and stops the clock:

1. Stops Claude Code's 30-day reaper (sets `cleanupPeriodDays` to 3650 in `~/.claude/settings.json`) and copies every transcript it can still reach into `~/.stratless/archive/`, outside the cleanup's reach. Whatever has already aged out is gone. This is the only part you cannot do later.
2. Add `--auto` and it also installs the after-session refresh: what's new gets judged in the background when a session ends, and the profile rebuilds once enough has changed. Plain `init` arms nothing in the background; that is yours to turn on.

To undo: set `cleanupPeriodDays` back to `30` and delete `~/.stratless/archive/`. That is all it touched.

## `profile` and `profile --read`

```
stratless profile          the AI's copy, what update loads into its context
stratless profile --read   your copy, written for you to read
```

**`profile` is free to look at.** It prints the last built rendering instantly, at zero spend, under a header that carries the build's own date and numbers. `profile` is the AI's copy, what `update` loads into its context; `profile --read` is your copy, the same evidence written for you, where it talked over your head and where you went quiet, and when the file has recently been wrong about you, the read says so. Neither loads anything: `profile` looks, and it ends by saying honestly whether a profile is loaded. Loading is `update`'s job.

`profile --read` renders lazily. Your profile earns the build; the human copy is written only when you ask for it, once per build, over exactly the evidence the loaded profile saw, so it can never describe a different picture than the profile you are running. After that first render it too is free to look at, until the next build. `profile` itself never rebuilds — rebuilding and loading is `update`'s job. Only `update` (with or without `--now`), and that first `--read` after a build, ever spend. Before any run makes a fresh read of your history, it says so first — `about to read 37 new exchanges on your own claude` — so the bill is announced, never discovered. See [HUMAN.md](/docs/human-md).

## `update`

```
stratless update         judge what's new; rebuild + load the profile when it's due
stratless update --now   rebuild + load right now, no questions
```

Judges whatever is new since last time (each exchange once, then cached), and rebuilds the profile only when it's due: **25 new judgments** since the last build, a profile more than a week old with anything new in it, or no profile on disk yet. A gated skip is not an off state; the existing profile stays loaded, only the rebuild spend is skipped. This is what the after-session refresh runs for you.

Since 0.3.5 the work runs in **one background worker** that `update` wakes and watches — your terminal is a window onto it, not the engine. On a normal run you notice nothing: same progress lines, same closing summary. The difference is at the edges: **Ctrl-C or closing the terminal detaches the display, and the work finishes anyway** — the profile still lands a few minutes later. The detach message shows the whole ladder: watch it with `stratless status`, stop everything with `stratless stop`. There is no daemon; the worker does its bounded job and exits. Sleep pauses it for free; nothing already judged is ever lost.

Every run that spends closes with its receipt — tokens, the API-equivalent cost, and which models actually ran — and `status` keeps the most recent one under `last run spend`, so even the silent after-session refreshes stay accounted for.

Since 0.3.0 a rebuild is a derivation, not an impression: the judgments are mined into named patterns with real counts and receipts, a separate pass audits the evidence, and the profile is written from what survives. If the writer invents a number that is not in the evidence — or returns chatter instead of a profile — **the build is refused** and your old profile stays loaded. Nothing lies, and nothing malformed ever loads.

Tune it: `STRATLESS_SYNTH_EVERY` changes the 25; `STRATLESS_SYNTH_MODEL` picks the model that writes the profile.

## `patterns`

```
$ stratless patterns

  your patterns   (23 admitted · 6 candidates · last mined 2026-07-17)

  WHAT THEY KNOW
    1. Drives releases end to end: tags, npm publishes, CI checks
       14x · 2026-06-24 → 2026-07-17 · steady · durable · high · audited 14/14
       prove it: stratless receipt 1

  FAILURE SIGNALS
    2. Redirects to a concrete task when an answer runs long or abstract
       9x · 2026-06-28 → 2026-07-16 · rising · durable · high · audited 8/9
       prove it: stratless receipt 2

  + 6 candidates below the evidence bar · see them with --all

  Every line traces to real exchanges through its receipts. No receipt, no claim.
```

The evidence your profile stands on, made inspectable. Each claim carries a real count, a time window, a trend, and **receipts**: the exchanges that witnessed it. The split is strict: the model names the pattern, the code counts it, so no number can be hallucinated. A claim needs **5 receipts** to exist at all; anything thinner is a candidate (an anecdote is not a category) and is never shown to the profile writer. See them anyway with `--all`. Reads a local file; spends nothing.

## `receipt`

```
$ stratless receipt 2

  Redirects to a concrete task when an answer runs long or abstract
  9 receipts · showing 3 (--all for every one)

  ── 2026-07-02 · session 91e0b3d4 ─────────────
  YOU ASKED     is there a cleaner way to structure the sync layer?
  IT SAID       There are three schools of thought here. The first, popularized by …
  YOU REACTED   just show me the diff for option two
```

Prove any claim. Give it a number from `patterns` and it dereferences the receipts back to the raw exchanges — what you asked, what it said, how you reacted — re-read from your own transcripts. A hash prefix works too (`stratless receipt 3f9a`), git-style. Free; zero model calls; local reads only.

One honest edge: if a receipt points at a transcript that was deleted by Claude Code's 30-day cleanup *before* your archive existed, the judgment survives but the raw exchange is gone — and the command says exactly that. It is what `init` protects against.

## `stop`

```
stratless stop
```

The off switch. If a refresh is running right now, it is stopped **within seconds** — spending halts immediately, and nothing paid-for is wasted: every judgment already made is banked forever, and restarting later re-reads at most one small chunk. Then the after-session refresh is removed and the profile is unloaded from your `CLAUDE.md`. Your `HUMAN.md` file is left as is; delete it yourself if you want it gone. Being able to shut it up completely, mid-run, is half of why you can trust it.

## `status`

```
$ stratless status

  stratless status

    after-session refresh   on
    profile loaded          yes  ~/.claude/HUMAN.md
    exchanges judged        1,412
    last refresh            2026-07-16
    spent so far            2.1M tokens across 1,412 reads  ≈ $2.06 at API rates, on your own claude
                            judging $0.91 (1,410) · profile builds $1.15 (2)
```

stratless's own state: whether the refresh is on, whether your profile is actually loaded, and what it has consumed of your borrowed `claude`. Tokens first, because a subscription spends quota, not dollars; the dollar figure is the API-equivalent, labelled as exactly that, split into judging and profile builds. The meter also confesses its own blind spots: if a call ever degrades to a path with no receipt, or runs on your default model because a requested one wasn't available, a `fallback calls` line says so the moment it happens. And if a cache file on disk is ever damaged, `status` labels it unreadable rather than showing a confident zero. Every line is read locally; plain `status` is fully offline and spends nothing. (`stats` below counts your *assistant's* activity in a project; `status` is about stratless itself.)

Add `--check` and it makes exactly one announced request to the npm registry to tell you whether a newer version exists. That is the only way plain-`init` users ever touch the network beyond their own `claude` — you ask, it checks, on screen.

## `stats`

```
$ stratless stats

  Your assistant, in this project

    lines it wrote            189,592
    edits it made               6,348
    files it touched            1,073
    sessions                       80
    days                           36

    archive reaches back to 2026-06-09, anything older was deleted by the cleanup.
```

Raw counts, instant and free (no tokens spent). The `archive reaches back to` line is the oldest transcript stratless can still find. Run `init` and it stops moving.

## Flags

```
stratless --version    print the installed version (short: -v)
stratless --help       the command list (also: -h, help)
```

Output through a pipe or with `NO_COLOR` set carries no color codes — `stratless status | grep loaded` gives you clean text.
